# Add SoloDesk to your device — 20 October 2026

Added an Add to Home Screen card on login, Settings and More. A module-level install controller captures the browser's deferred prompt, including events received before visiting Settings. Prompting only happens from the user's button click. Acceptance is distinguished from the actual `appinstalled` event; cancelled/failed prompts recover to manual instructions. Standalone mode is detected without storing a tracking flag.

The guide has iPhone/iPad, Android and desktop choices. iOS explains Safari's Share → Add to Home Screen and Open as Web App when present. Desktop includes Chrome/Edge and Safari Add to Dock. Embedded/unsupported browsers retain instructions. Platform detection recognizes iPads with desktop-class user agents.

The root web manifest supplies a stable origin-scoped ID, root scope, dashboard start URL, standalone display and 192/512px icons. A separate maskable icon and 180px Apple touch icon are rendered from the existing vector mark, with platform-mask padding. Apple launch metadata and standalone safe-area CSS are included. No service worker, offline data cache, analytics or notification permissions were added. This implements installation, not offline workspace functionality; internet is still required to load/sync. The existing Google authentication and shared database are unchanged.

Verification: 61 automated tests and production build pass. Seven new checks cover platform detection, fallback, deferred/single-use prompts, dismissal, acceptance vs installation, errors, installed mode/subscribers and actual manifest PNG sizes. Browser checks exercised login/More/Settings entry points and all three device guides. The Android guide fit a 320px viewport without horizontal overflow. A 390px Settings review caught inherited block formatting on bold instruction text; an explicit inline style corrected it. Screenshot: `screenshots/add-to-home-2026-10-20.png`.

Native installation dialogs, OS shortcut creation and standalone Google login were not exercised on physical Windows/macOS/iOS/Android devices; the in-app browser offers the manual fallback. Prompt lifecycle tests use a fake event source. Browser support and installation prompts remain controlled by the browser.
